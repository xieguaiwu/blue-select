# blue-select

**English** | [中文](README_zh.md)

Bluetooth headphone one-shot connect & audio switch for Linux (bluez + PipeWire/PulseAudio). Written in Go, zero third-party dependencies.

## Problem it solves

1. **Connected but sound still plays from speakers** — connecting via `bluetoothctl` does not switch PulseAudio/PipeWire default output. blue-select waits for the bluez sink, sets it as default and moves all existing playback streams.
2. **Manual reconnect after sleep/wake** — one command: `blue-select connect`.

```bash
# Connect device (fuzzy name match) and switch audio output
blue-select connect freearc

# Disconnect device; default output falls back to a local sink
blue-select disconnect freearc

# Show devices, battery, A2DP profile, sinks and default output
blue-select status

# Daemon: auto-switch to any newly connected Bluetooth sink
blue-select watch

# Install watch as a systemd user service
blue-select install
```

First successful `connect <name>` records the device and makes it the default (`~/.config/blue-select/config.json`). Later plain `blue-select connect` reconnects it.

## Configuration

`~/.config/blue-select/config.json`:

```json
{
  "default_device": "HUAWEI FreeArc",
  "devices": { "HUAWEI FreeArc": "AA:BB:CC:DD:EE:FF" }
}
```

## systemd service

```bash
systemctl --user status blue-select-watch
journalctl --user -u blue-select-watch -f      # follow switch log
systemctl --user restart blue-select-watch
```

The unit is regenerated by `blue-select install` (ExecStart points at the binary path that ran install — re-run install after moving the binary).

## Build & install

Requirements: Go 1.22+, Linux with `bluetoothctl` (bluez) and `pactl` (PipeWire pipewire-pulse or PulseAudio).

```bash
go build -trimpath -ldflags="-s -w" -o ~/.local/bin/blue-select .
go test ./...
```

## Known limitations

- If the headphone is currently connected to your phone, it may refuse the computer connection (no broadcasting / connection race). Disconnect it on the phone first.
- `watch` only switches audio routing; it does not reconnect the headset. Reconnection relies on bluetoothd auto-reconnect for trusted devices.
- Non-interactive subcommands only; no TUI.

## Troubleshooting

**Error "pairing key missing" (underlying `br-connection-key-missing`)**

The pairing record is corrupt. Remove it and pair again:

```bash
bluetoothctl remove <MAC>
# Put the headset in pairing mode. For FreeArc: both buds in the case, lid open, hold the case button 2-5 s until the LED flashes white.
```

BlueZ asks you to confirm a 6-digit passkey (`Confirm passkey 123456 (yes/no)`) and needs a `yes` answer. When you pipe commands in, this prompt swallows your next command — use a script that answers it automatically. See the `bluetooth-pairing-troubleshoot` skill.

**No devices found while scanning / occasional connect timeouts**

USB autosuspend on Intel Bluetooth adapters causes this (kernel log: `hci0: Reading supported features failed (-16)`). Fix it with the script below. It needs sudo, takes effect immediately, and survives reboot:

```bash
sudo bash ~/Downloads/fix-bluetooth-usb-autosuspend.sh
```
